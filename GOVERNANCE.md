# Proposed project governance

Asimov governance is maintained through public issues, pull requests, releases, and Asimov Enhancement Proposals.

The initial repository is maintainer-led. Before public release, it needs an actual maintainer roster, public discussion venue and private security-reporting route. No committee, external reviewer, sponsor or certification authority is claimed by this document.

Normative changes use an Asimov Enhancement Proposal (AEP). A proposal identifies the affected requirement IDs, problem/evidence, proposed wording, test changes, interoperability consequences, compatibility impact and unresolved objections. Decisions and dissent should remain public unless they expose a live vulnerability or sensitive information.

A specification release and a test-catalog release are versioned independently in principle; this initial draft pins them to the same version. Changing a test family or its applicability cannot silently alter the meaning of an old result. An implementation version is not a standards version.

Before a stable release, the project should recruit independent technical reviewers and adopt a balanced, documented decision process. Contributions from a vendor do not grant exemptions or privileged control of test outcomes. Financial relationships and assessment conflicts should be disclosed.

No certificates, badges, accredited assessors or trust registry are issued by the founding repository. Establishing any of these would require a separate public proposal addressing assessor independence, evidence validation, appeal, suspension, misleading claims and governance.

Original contributions use the repository's Apache-2.0 license unless a future reviewed change specifies otherwise. A standards-appropriate patent/contribution policy and name review remain pre-release governance tasks; the current license should not be represented as resolving every future standards-essential patent question.

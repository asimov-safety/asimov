# GitHub Pages site plan

The repository is the normative source. The website renders the current tagged specification and tooling for human use.

## v1 navigation

1. **Home** — thesis, Seven Constants, A-level ladder, current implementation.
2. **Seven Constants** — plain-language Constant treatments linked to normative requirements.
3. **A1–A5** — cumulative profile definitions and mandatory-family counts.
4. **Test Your System** — install, map infrastructure, build adapter, run readiness/probes.
5. **Probe Explorer** — all 42 families with implementation status.
6. **Verification** — evidence integrity, signer identity, checkpointing, semantic assurance.
7. **Status** — executable coverage, portability milestone, roadmap.
8. **Contribute** — adapters, tests, AEPs, review.

## Design rules

- Every website requirement links to versioned repository source.
- Profiles use mandatory pass/fail criteria rather than numeric safety scores.
- Missing mandatory control surfaces are blockers.
- Results distinguish assessment mode and verification state.
- Visual identity stays restrained, technical, and infrastructure-like.
- Static files keep deployment simple and durable on GitHub Pages.
